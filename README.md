# CatWoman Cloudflare

پنل مستقل CatWoman برای **Cloudflare Workers + D1** با تونل واقعی **VLESS روی WebSocket/TLS**.

این مخزن کاملاً جدا از نسخه Railway است و هیچ فایل یا دیتایی از پروژه Railway را تغییر نمی‌دهد.

## امکانات نسخه اول

- تونل VLESS روی WebSocket و خروجی TCP با `cloudflare:sockets`
- ساخت خودکار جداول در Cloudflare D1
- راه‌اندازی اولیه مدیر، ورود امن، Session و CSRF
- ساخت، ویرایش، فعال/غیرفعال و حذف کاربر
- محدودیت حجم، تاریخ انقضا و محدودیت تقریبی دستگاه
- لینک مستقیم VLESS، لینک سابسکریپشن، QR و صفحه اختصاصی کاربر
- ثبت مصرف، تعداد اتصال و آخرین زمان فعالیت
- بخش واقعی «هاست‌ها» برای ساخت چند مسیر اتصال روی هر کاربر
- ساخت، ویرایش، تکثیر، حذف، فعال/غیرفعال، پیش‌فرض، ترتیب و مخفی‌کردن هاست از اشتراک
- تنظیم جداگانه Address/Clean IP، Port، SNI، Host Header، WS Path، TLS، Fingerprint، ALPN و Allow Insecure
- تولید لینک و QR جدا برای هر هاست و سابسکریپشن چندکانفیگی
- تنظیم دامنه عمومی، Clean IP و Proxy IP اختیاری به‌عنوان حالت سازگار قدیمی
- اعلان تلگرام و فایل پشتیبان JSON شامل کاربران، تنظیمات و هاست‌ها
- رابط رسمی CatWoman برای موبایل و دسکتاپ

## نصب از گوشی با GitHub → Cloudflare

1. وارد **Cloudflare Dashboard** شوید.
2. بخش **Workers & Pages** را باز کنید.
3. روی **Create** و سپس **Import a repository** بزنید.
4. GitHub را وصل و مخزن `catwomanZ/catwoman-cloudflare` را انتخاب کنید.
5. شاخه تولید را روی `main` بگذارید.
6. تنظیم‌ها:
   - **Root directory:** خالی یا `/`
   - **Build command:** `npm run check`
   - **Deploy command:** `npx wrangler deploy`
   - **Node version:** `22` یا بالاتر
7. Deploy را بزنید.

`wrangler.jsonc` اتصال `DB` را بدون شناسه تعریف کرده است؛ در اولین Deploy، Cloudflare می‌تواند D1 را خودکار بسازد و به Worker وصل کند. جداول نیز در اولین درخواست به‌صورت خودکار ساخته می‌شوند.

بعد از Deploy:

1. آدرس Worker را باز کنید.
2. صفحه `/setup` نمایش داده می‌شود.
3. نام کاربری و رمز مدیر را بسازید.
4. وارد پنل شوید و در بخش **هاست‌ها** مسیرهای اتصال را بسازید.
5. اولین کاربر را ایجاد کنید.
6. صفحه اشتراک یا QR همان کاربر را در کلاینت وارد کنید.

اگر هنوز هاستی نسازید، تنظیمات قدیمی «شبکه Edge» بدون تغییر کار می‌کند؛ بنابراین کاربران و لینک‌های فعلی پس از بروزرسانی خراب نمی‌شوند.

## تنظیم Custom Domain

اگر Custom Domain دارید:

1. آن را از Cloudflare به Worker وصل کنید.
2. داخل پنل به **تنظیمات ← شبکه Edge** بروید.
3. دامنه را در «دامنه عمومی Worker» وارد کنید.
4. اگر لازم است، Clean IP را جداگانه در «آدرس ورودی» بگذارید.

در این حالت، `Host` و `SNI` همچنان دامنه Worker می‌ماند تا TLS معتبر باشد.

## هاست‌های چندگانه

در بخش **هاست‌ها** می‌توانید چند endpoint عمومی برای همان تونل Worker بسازید. برای نمونه:

- هاست مستقیم با دامنه Worker
- Clean IP با `SNI` و `Host Header` دامنه Worker
- دامنه یا مسیر WebSocket متفاوت مثل `/cdn`

هر هاست فعال که گزینه «در سابسکریپشن نمایش داده شود» دارد، یک لینک VLESS جدا برای همه کاربران می‌سازد. Path نهایی خودکار به شکل زیر تولید می‌شود:

```text
<WS Path>/connect/<subscription-token>
```

انتخاب یک هاست به‌عنوان پیش‌فرض، آن را فعال می‌کند. خاموش یا مخفی‌کردن یک هاست آن را از سابسکریپشن حذف می‌کند و هیچ کاربری را پاک نمی‌کند.

## اجرای محلی

نیازمندی: Node.js 22 یا بالاتر.

```bash
npm ci
npm run dev
```

سپس `http://localhost:8787` را باز کنید.

## آزمون‌ها

```bash
npm run check
npm run dry-run
```

آزمون دستی مسیر کامل تونل، پس از ساخت کاربر و گرفتن لینک:

```bash
VLESS_LINK='vless://...' node scripts/live-tunnel.mjs
```

در آزمون نهایی ۱۸ اکتبر ۲۰۲۶، هر دو مسیر محلی و واقعی Cloudflare موفق بودند:

`VLESS client → WSS Worker → cloudflare:sockets → neverssl.com:80`

روی Worker واقعی پاسخ `HTTP/1.1 200 OK` دریافت شد، **۴۲۶۸ بایت** برگشت و **۴۳۵۷ بایت** مصرف همراه با یک اتصال در D1 ثبت شد. اسکریپت `scripts/live-tunnel.mjs` همین مسیر را دوباره آزمایش می‌کند.

## محدودیت‌ها

- فقط TCP پشتیبانی می‌شود؛ UDP عمومی و تماس مستقیم پشتیبانی نمی‌شود.
- محدودیت دستگاه بر پایه IPهای فعال در ده دقیقه اخیر است و تقریبی محسوب می‌شود.
- D1 برای آمار مدیریتی مناسب است، اما مصرف اتصال‌های هم‌زمان ممکن است با کمی تأخیر نمایش داده شود.
- فایل پشتیبان، رمز مدیر و توکن بات تلگرام را صادر نمی‌کند.
- `cloudflare:sockets` اجازه اتصال مستقیم به بازه‌های IP خود Cloudflare را نمی‌دهد؛ برای مقصدهایی که پشت Cloudflare هستند ممکن است تنظیم یک Proxy IP مطمئن لازم باشد.
- Proxy IP اختیاری است و باید فقط از منبع مطمئن استفاده شود.

## امنیت

- رمز مدیر با PBKDF2-SHA256 و Salt تصادفی ذخیره می‌شود.
- Session فقط با Cookie امن، `HttpOnly` و `SameSite=Strict` نگهداری می‌شود.
- درخواست‌های مدیریتی CSRF و Same-Origin بررسی می‌شوند.
- مقصدهای محلی، خصوصی، Metadata و پورت ۲۵ در تونل مسدود هستند.
- UUID و توکن اشتراک هر کاربر مستقل است و از پنل قابل تعویض است.

## نکته مهم Cloudflare

استفاده از سرویس به‌عنوان VPN/Proxy ممکن است طبق نوع حساب و شرایط Cloudflare نیازمند مجوز باشد و خطر محدودشدن حساب را داشته باشد. پیش از استفاده عمومی، شرایط حساب خود را بررسی کنید.

## معماری

```text
Client VLESS/WSS
      ↓
Cloudflare Worker (authentication + protocol parser)
      ↓
cloudflare:sockets (outbound TCP)
      ↓
Internet

Admin UI / Subscription
      ↓
Cloudflare Worker
      ↓
Cloudflare D1
```

هسته تونل این پروژه Clean-room است و از سورس Zeus یا Nova کپی نشده است.
